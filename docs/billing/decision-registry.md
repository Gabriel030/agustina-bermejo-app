# Registro de decisiones de facturación

Fuente de verdad de las decisiones de negocio de facturación, cobranza, matrículas y cuotas (D-170). La Bitácora de preguntas, las contradicciones y los pendientes viven en la nota de Obsidian "Registro de decisiones de facturación"; esta tabla es el contrato que verifica la CI.

## Reglas de mantenimiento

1. Todo PR que agrega, reemplaza o implementa una decisión actualiza este archivo en el mismo PR. Una respuesta nueva de Gabriel entra primero en la Bitácora de Obsidian y su fila acá, el mismo día.
2. Una fase que implementa una decisión cambia su Implementación a `implementada` o `parcial (...)` en su PR; desde ese momento `BillingDecisionCoverageTest` exige un test con `@Tag("D-xxx")`.
3. Las decisiones no se borran: una que cambia queda `reemplazada por D-yyy` y la nueva entra con ID propio.
4. Los tests de billing llevan `@Tag("D-xxx")` por cada decisión que verifican, y `@Tag("contradicts-D-xxx")` cuando afirman el comportamiento contrario de una decisión marcada `violada (...)`.

## Gramática de columnas

| Columna | Valores |
|---|---|
| ID | `D-` y tres dígitos, único |
| Estado | `vigente`, `a confirmar`, `pendiente`, `reemplazada por D-xxx[, D-yyy]`, `resuelta por D-xxx[, D-yyy]` |
| Configurable | `no`, `sí`, `sí (<detalle>)` |
| Implementación | `implementada`, `parcial (<fase>)`, `pendiente (<fase>)`, `violada (<fase>): <archivo:línea>`, `no aplica` |
| Caso de test | Dado/Cuando/Entonces; obligatorio si Estado es `vigente` o `a confirmar` e Implementación no es `no aplica` |

Un `|` dentro de una celda se escribe `\|`.
