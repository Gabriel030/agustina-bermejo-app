# #1196 T#1 — Token de activación y canje público

## Criterios de aceptación
- [x] Tabla `activation_token` (V426), solo hash SHA-256 en DB
- [x] Puerto `identity.api.ActivationTokenIssuer`: token URL-safe de 32 bytes, vence en `auth.activation-token-expiration-days` (default 7), reemitir invalida el anterior, rechaza personas con password
- [x] `POST /auth/activate` público: setea password, `emailVerified=true`, `grantSystemAccess=true`, marca el token usado
- [x] Errores `ACTIVATION_TOKEN_INVALID` / `ACTIVATION_TOKEN_EXPIRED` (400), `PERSON_ALREADY_ACTIVATED` (409, solo puerto)
- [x] Cuerpo de INVALID idéntico entre token inexistente, usado, persona activa, mail cambiado o cambio de mail en curso. INVALID vs EXPIRED solo lo distingue quien ya posee un token real de 256 bits.
- [x] Elegibilidad en emisión (ACTIVE, rol ALUMNO, sin password, con mail); el canje exige ACTIVE, mismo mail que al emitir y sin cambio de mail ajeno en curso
- [x] El canje revoca sesiones y evicta el caché de acceso (SessionRevoker)
- [x] Emisión serializada por persona con lock pesimista; doble canje paralelo: gana uno solo
- [x] Rate limit por IP en `RequestRateLimitFilter` (`/auth/activate`)
- [x] Matriz de autorización, openapi.json, error-catalog y `domainErrorMessages.js`
- [x] Sabotaje: sin la verificación de vencimiento cae `anExpiredTokenIsRejected...`
