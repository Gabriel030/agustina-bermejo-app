## Criterios
- [x] Una delivery vencida referenciada por un `broadcast_recipient` vivo no se borra y el job no falla: `deliveryReferencedByALiveRecipientIsKeptAndTheJobDoesNotFail`
- [x] Cuando el recipient ya no existe, la delivery se borra en la corrida siguiente: `deliveryIsDeletedOnceItsRecipientIsGone`
- [x] Las deliveries sin referencia siguen igual (mismo test y `oldTerminalDeliveriesAreDeletedButQueuedDeferredAndRecentOnesStay`)
- [x] Sabotaje: sin el filtro los dos tests nuevos fallan por `broadcast_recipient_delivery_id_fkey`

## Notas
- Sin migración ni contrato. Solo `NotificationDataRetentionJob` (condición de selección de `OTHER_DELIVERIES`) y `DataRetentionIT`.
- El filtro solo aplica a las deliveries que no son de cobranza: un masivo nunca usa la categoría `COLLECTION_REMINDER`.
- Las deliveries referenciadas se borran después de que 933#3e (#1036) purgue al recipient.
