## Notas / decisiones
- Sin migración nueva: usa V445 de N1a.
- Bloqueo del alumno por el mismo candado de fila (requireByIdForUpdate) para que dos pedidos simultáneos no esquiven el límite diario.
- Llaves { } en el destinatario se rechazan (400): el motor E1 expande marcadores con replace secuencial y un texto literal las interpretaría.
- Decisión del líder: el enum PublicCertificateDocumentKind, openapi y la fuente de verificación salen de este PR (V1 #1369 define los 5 kinds).
- Seguimiento: expansión de marcadores en una sola pasada en el motor de E1 (hoy se rechazan llaves en recipientText con 400 INVALID_EXAM_REGISTRATION_RECIPIENT).
- Sin número de registro (registry_number queda null).
- /me/documents se despacha con un if por tipo en GenerateOwnDocumentService; la descarga y el listado van por el despachador de T1a (ApprovedProcedureSources).
- Evaluador, emisor y proveedor de PDF viven en procedure.specialist (evita el ciclo certificate↔procedure).
- Pregunta de producto abierta: si ya hay un documento vigente para la inscripción, pedir otro destinatario devuelve el mismo documento sin cambiarlo (límite 1/día). Fijado con un test.
